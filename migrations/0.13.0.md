# Migration 0.13.0 — Implement Command

## Context

Pdeq 0.13.0 adds the **Implement** feature: a `/pdeq-implement` slash command and a `scripts/implement-context.sh` context producer that turn reviewed specs into implementing code in one step. Kickoff ends at reviewed specs with a reminder to add inline markers; implement closes that gap by joining git spec-diff scope against the traceability index and handing a complete, single-pass context bundle to the implementing agent, which then writes code, adds markers, runs the engineering/QA loop, and re-runs the traceability audit as the done-check.

**This migration is advisory** (`breaking: false`). The new script and command are installed automatically when the `.pdeq` submodule is bumped. The command does not run automatically — the consumer invokes `/pdeq-implement` when ready to build from reviewed specs. Existing projects are not affected unless they opt in.

**What ships in the diff for a consumer:**
- New: `scripts/implement-context.sh` — the context producer (joins git spec-diff scope against the index, emits one deterministically-ordered bundle to stdout).
- New: `pdeq-rules/commands/pdeq-implement.md` — slash command prompt that shells out to the script and drives the implementing agent.
- New: materialized symlinks `.claude/commands/pdeq-implement.md` and `.pi/prompts/pdeq-implement.md` (Claude and Pi harnesses).
- New: `engineering/apps/cli/tests/implement/` — the 22-case shell test suite (runs in CI, no consumer action needed).

No existing files are modified by this release. No config field is added. No spec format changes. The feature reads `pdeq.json`'s existing `specsRoot` and the existing traceability index; it writes nothing to disk.

## Mechanical

No mechanical transforms. The new script, command, and test suite are installed automatically when the `.pdeq` submodule is bumped. There is nothing for the consumer to apply to their specs or config.
