# Migration 0.15.0 — Automated lane-audit finding triage

## Context

Pdeq 0.15.0 adds an optional middle tier to lane discipline: **automated finding triage**. The lexical backstop (`scripts/audit-lanes.sh`) has always had a documented blind spot — a grep cannot tell a real violation from a legitimate mention (an overview sentence naming a host for orientation, or a per-host constraint in an NFR). When a project sets `laneAudit.jevTriage: true` in `pdeq.json` and the `jev` judgment CLI is installed, each flagged line is additionally classified by an external low-cost judgment service. Findings answered as a legitimate mention at high confidence are demoted to labeled `✓ allowed (jev triage: …)` notes; a violation answer, low confidence, or any service failure keeps the `⚠` finding verbatim — triage can only demote, never hide.

**This migration is advisory** (`breaking: false`) and **mechanically a no-op**. The feature is opt-in configuration: a project that does nothing keeps the exact pre-0.15.0 audit behavior (deterministic, no network). A project that wants automated triage flips the flag itself — enabling it is a cost/dependency decision (each finding costs ~450 input tokens to the shared judgment provider), so it is deliberately not seeded by this migration.

## Mechanical

None. `laneAudit.jevTriage` defaults to false and its absence is indistinguishable from false, so there is no scaffolding to seed. Consumers adopt it by adding `"jevTriage": true` inside their existing `laneAudit` object when (and only when) they want it.

## Notes

- The blocking structural check (`scripts/audit-structure.sh`) and the downstream lane scan are untouched — they never consult the judgment service, preserving their determinism.
- The advisory prompt-guided lane review (Layer 2) is untouched and remains the authoritative judgment of context; triage only pre-clears obvious legitimate mentions.
- The demotion threshold (confidence >= 0.85) is a framework constant, not project configuration.
- Also shipping in this release: the **conformance alignment pre-screen** (`scripts/alignment-check.sh`) — a per-slice requirement-vs-code drift check that pairs each indexed requirement with its cited code and classifies the slice as aligned or drift. It needs no setup: there is no config field and no hook ever calls it — invocation is the opt-in (`FR-conformance-jev-opt-in`), via `/pdeq-conform` or running the script directly. A project that never invokes it makes no judgment-service calls. Its judgment service is the same `jev` CLI the lane triage uses, so no separate setup exists.
