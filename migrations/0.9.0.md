# Migration 0.9.0 — Platform conformance audit

## Context

Pdeq 0.9.0 adds the **conformance audit**: an advisory quality review, invoked as `/pdeq-conform <platform> [feature]`, that reasons about a platform's source code against that platform's specs and reports a four-quadrant conformance matrix — **fulfilled**, **unfulfilled**, **incorrectly fulfilled** (verdicts per requirement), and **undocumented** behavior (reverse traceability). It is the semantic counterpart to the deterministic traceability audit: where `scripts/audit-traceability.sh` checks *does a marker exist and is the slug valid* (lexical, commit-blocking), the conformance audit checks *does the code behave the way the requirement says* (judgment-based, **never gating**). It is the fourth pdeq quality reviewer, alongside the Reviewer, Consistency Checker, and Lane Reviewer.

The feature ships as two prose artifacts: a new **Conformance Reviewer** role in the canonical root `AGENTS.md` §"Quality Subagents", and a new command source file `pdeq-rules/commands/pdeq-conform.md`. See `product/conformance.md` for requirements and `engineering/cli/conformance.md` for the contract.

**This change is non-breaking.** It adds an optional advisory command; nothing in an existing consumer's specs, config, or commit path changes, and nothing is required of a consumer who never runs it.

## Notes

- **Why advisory / changes no files.** The new command reaches a consumer through the existing harness materialization path. `pdeq-rules/commands/pdeq-conform.md` is a new command source file, so the next `/pdeq-update` (which runs `scripts/sync-symlinks.sh --prune`) materializes it into each command-supporting harness's directory (`.claude/commands/`, `.pi/prompts/`) automatically — the same path every other `pdeq-*` command uses. The Conformance Reviewer role rides along in the canonical `AGENTS.md`, which every harness already reads through its symlink/import. No installer edit and no consumer file edit are needed, so this migration authors no changes. Per the advisory-migration class (see `product/migrations.md`), it rides the lineage MINOR bump without being consumer-breaking.
- **How to use it.** After bumping the pin (and running `/pdeq-update`), run `/pdeq-conform <platform>` — e.g. `/pdeq-conform cli` — to get a conformance report for that platform, or `/pdeq-conform <platform> <feature>` to focus on one feature. The report is advisory: it never blocks a commit and never modifies your specs or code.
- **Relationship to the deterministic audit.** The conformance audit complements, never replaces, `scripts/audit-traceability.sh`. It reads that audit's outputs (the `index.md` `Code` column, the engineering Code Maps) as its starting point but never modifies them or changes the coverage gate.
