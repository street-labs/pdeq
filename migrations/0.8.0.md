# Migration 0.8.0 — Pi slash commands + skill

## Context

Pdeq 0.4.0 modeled Pi as command-less — a twin of Codex — on the premise that Pi's slash-command surface was a code-based (TypeScript) extension. That premise was wrong. Pi reads **markdown prompt templates** from `.pi/prompts/*.md`, where the filename becomes the command name and `$ARGUMENTS` / `$1` expand — the same shape as pdeq's command source files under `pdeq-rules/commands/`.

0.8.0 corrects this. The harness adapter (`scripts/lib/harness.sh`) now returns `.pi/prompts` as Pi's commands directory instead of empty, so a Pi-enabled project gets a native, tab-completable `/pdeq-*` palette. The same release also exposes the pdeq setup skill at Pi's discovery path (`.pi/skills/pdeq/SKILL.md`), a relative symlink to the canonical `.claude/skills/pdeq/SKILL.md`. See `product/harness-agnostic.md` (`FR-harness-agnostic-commands-per-harness`, `FR-harness-agnostic-skill-claude-pi`).

**This change is non-breaking.** A project with no `pi` in its `harnesses` list is unaffected. A project that already lists `pi` gains capability, loses nothing: the previous behavior (invoke pdeq workflows in prose) still works, and now the palette works too.

## Notes

- **Why advisory / changes no files.** The corrected adapter reaches an existing consumer automatically when it bumps the submodule pin — `scripts/lib/harness.sh` is a symlink into `.pdeq/`. The consumer's `.pi/prompts/` palette is then materialized by the next `scripts/sync-symlinks.sh` run, which `/pdeq-update` already invokes with `--prune`. Because both `init.sh` and `sync-symlinks.sh` were already generic over the harness adapter, no installer-body change was needed and this migration authors no file edits. Per the advisory-migration class (see `product/migrations.md`), it rides the lineage MINOR bump without being consumer-breaking.
- **For a Pi consumer already installed before 0.8.0.** Run `/pdeq-update` (or re-run `scripts/init.sh`). Either materializes `.pi/prompts/pdeq-*.md`. After that, type `/pdeq` in Pi's palette to see the full command set.
- **Skill.** The Pi skill surface is a symlink to the single canonical `SKILL.md`; there is one authored file, two harness views. Codex CLI has no skill concept and receives nothing.
