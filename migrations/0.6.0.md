# Migration 0.6.0 — Structural lane enforcement becomes blocking

## Context

Pdeq 0.6.0 adds *structural correctness* enforcement to the spec graph (see `product/spec-structure.md` and the extended `product/lane-discipline.md`). Two things change for a consumer:

1. **A new blocking check** — `scripts/audit-structure.sh`, wired into `hooks/pre-commit`. Unlike the warn-only lexical backstop (`audit-lanes.sh`), it **blocks the commit** on high-confidence structural bleed: presentation/interaction or construction detail or platform-as-product framing in a shared product spec; engineering detail in a design spec; and product-requirement *definitions* in an engineering spec.
2. **A stronger kickoff** — the triage gate, overlap check, and per-lane "read the lane's AGENTS.md first" steps. These are prompt changes only.

**This is a breaking change for existing projects.** pdeq 0.5.0 deliberately shipped lane discipline as *warn-only* and left cleanup of existing bleed as a follow-up the project owned. Those projects therefore very likely carry bleed that this release will start **blocking**. The moment you bump the submodule pin, the blocking check is live — `scripts/`, `hooks/` (via `core.hooksPath` into the submodule), and the command/`AGENTS.md` text all propagate automatically with the bump, so no wiring step is needed; the behavior change is immediate.

**The escape hatch.** `PDEQ_ALLOW_DRIFT=1 git commit ...` demotes every structural block to a named warning for that one commit. This is the release valve while you clean up pre-existing bleed. It is the same variable that already governs the traceability audit, so there is nothing new to learn.

This migration does not edit any of your specs. Its Mechanical section (a) ensures the `laneAudit` config scaffold exists and (b) **runs the new check in report mode so you see exactly what will block your next commit** — nothing more. Acting on the report is your call.

## Mechanical

```shell
# 1. Seed an empty laneAudit scaffold into pdeq.json if absent. Idempotent:
#    a second run, or a project that already configured laneAudit (e.g. via the
#    0.5.0 migration), is left byte-for-byte unchanged. Inline python3, no jq.
python3 - <<'PY'
import json
path = "pdeq.json"
with open(path) as f:
    data = json.load(f)
if "laneAudit" in data:
    print("laneAudit already present in pdeq.json — no change")
else:
    data["laneAudit"] = {"vendors": [], "protocols": [], "platforms": [], "libraries": []}
    with open(path, "w") as f:
        json.dump(data, f, indent=2)
        f.write("\n")
    print("seeded empty laneAudit scaffold into pdeq.json")
PY
```

```shell
# 2. Report-only preview: run the new blocking structural check with the escape
#    hatch engaged, so it lists every violation that WILL block your next commit
#    without failing this migration. Read-only — changes no files, so it is
#    trivially idempotent. Skips cleanly if the script has not yet materialized.
if [ -x "./scripts/audit-structure.sh" ]; then
  echo "── Structural check preview (these will block commits at 0.6.0) ──"
  PDEQ_ALLOW_DRIFT=1 ./scripts/audit-structure.sh || true
  echo "── Fix the items above, or use PDEQ_ALLOW_DRIFT=1 to commit past them ──"
else
  echo "scripts/audit-structure.sh not present yet — re-run after the submodule bump materializes it."
fi
```

## Notes

- **Why breaking, not opt-in.** The maintainer chose enforcement-on-bump with an escape hatch over a default-off toggle, so that lane bleed cannot silently persist behind a flag nobody flips. The `PDEQ_ALLOW_DRIFT=1` valve makes the transition survivable without weakening the default.
- **What auto-propagates (no action needed).** `scripts/audit-structure.sh`, `scripts/lib/lane-scan.sh`, the edited `hooks/pre-commit`, and the kickoff/`AGENTS.md` prompt text are all symlinked from the submodule and reach the project the instant the pin is bumped. This migration exists for the version contract, the config seed, and the breaking-change preview — not to move code.
- **Precision.** The blocking defaults are deliberately narrow (they skip fenced code and permanent slug tokens, and exclude idiom-heavy words like "click"/"scroll"). Breadth comes from your own `laneAudit` terms and the advisory Lane Reviewer, not from widening the blocking defaults. If the check false-positives, `PDEQ_ALLOW_DRIFT=1` unblocks the commit and the finding can be reported.
