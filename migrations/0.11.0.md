# Migration 0.11.0 — QA Coverage Audit

## Context

Pdeq 0.11.0 adds the **QA Coverage Audit** (`scripts/audit-coverage.sh` + `scripts/audit-coverage.py`), which joins the marker-derived Code column from the traceability index against each feature's QA Coverage Matrix and blocks commits when a feature has realizing code but its coverage rows are non-terminal. It is the missing inverse of the requirement↔code mapping feature: where the traceability audit blocks on "code doesn't exist yet," this blocks on "QA hasn't been run yet."

**This migration is advisory** (`breaking: false`). The new scripts are installed automatically when the `.pdeq` submodule is bumped. They do not run automatically — the consumer project must add them to their CI pipeline and/or their pre-commit hook. Existing projects are not affected unless they opt in.

**What ships in the diff:**
- New: `scripts/audit-coverage.sh` — shell wrapper.
- New: `scripts/audit-coverage.py` — core audit logic (Python 3).
- New: `scripts/lib/qa-matrix.sh` — shared QA parser extracted from `audit-traceability.sh`.
- New: `pdeq-rules/commands/pdeq-coverage.md` — slash command prompt for interactive use.
- Modified: `scripts/audit-traceability.sh` — phase 7b QA parser extracted into shared library; no behavioral change.

### Prompt

You are migrating a pdeq consumer project to version 0.11.0, which adds the QA Coverage Audit.

The audit is a standalone deterministic script that checks whether QA has been executed for features that have realizing code. It reads the Code column of `index.md` (populated by inline markers) and compares it against each feature's QA Coverage Matrix (`qa/<platform>/<feature>.md`). When a feature has code but non-terminal coverage (any status other than "Pass" or "Fail"), it blocks.

**Your task:**

1. If the project has a CI pipeline (`.github/workflows/`, `.circleci/`, `Jenkinsfile`, etc.), add a step to run `./scripts/audit-coverage.sh --check`.
   - If the project's coverage matrices are known to be incomplete (many "Not started" rows for features with shipped code), add `PDEQ_ALLOW_DRIFT=1` to the invocation so existing gaps do not block. Add a comment explaining that this override should be removed once coverage is updated.
   - If the project is already disciplined about QA coverage, omit the override.
   - Example GitHub Actions step:
     ```yaml
     - name: QA coverage audit
       run: ./scripts/audit-coverage.sh --check
     ```
2. If the project uses a pre-commit hook that runs the other pdeq audits, optionally add a call to `./scripts/audit-coverage.sh`. This is optional — the audit is designed to run in CI, and adding it to the pre-commit hook is a per-project decision.
3. Do NOT modify any spec files, index.md, or the audit scripts themselves. This migration only wires the new audit into the project's automation.

Make NO changes to files that are already correctly configured. Silence means "already conformant."

End with exactly one summary line: `updated N of M files`.
