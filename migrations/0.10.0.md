# Migration 0.10.0 — Living Spec Discipline

## Context

Pdeq 0.10.0 introduces **living spec discipline**: specs describe the current state of features, not versioned plans or phased roadmaps. Temporal language like "MVP", "phase 1", "V2", "iteration 2" is now detected by a new audit (`scripts/audit-temporal.sh`) and **blocked at commit time by default**.

This migration is **breaking** because the temporal audit blocks commits when it finds temporal language, and existing projects likely have some. Consumers must either:

1. **Clean up temporal language** in their specs (rewrite in present tense or move to roadmap), OR
2. **Explicitly opt out** by setting `temporalAudit.blockCommit: false` in `pdeq.json`.

The migration also introduces **roadmap spec supplements** — optional, forward-looking spec content in `roadmap/` files with reserved slug prefixes (`FRR-`, `NFRR-`, `ACR-`) for multi-phase planning. These are exempt from traceability and can hold detailed future requirements without polluting current-state specs.

**What you'll see in the diff:**
- New script: `scripts/audit-temporal.sh`
- Extended: `scripts/audit-traceability.sh` (skips roadmap slug prefixes)
- Updated: `roadmap/AGENTS.md` (documents roadmap spec supplements)
- Updated: `pdeq-rules/commands/pdeq-kickoff.md` (temporal audit in Step 4)
- Updated: `product/AGENTS.md` (present-tense guideline)
- Possibly: `pdeq.json` with `temporalAudit.blockCommit: false` if you opt out
- Possibly: `pdeq.json` with `temporalAudit.exclude` or `temporalAudit.include` for project-specific customization

## Mechanical

No mechanical transforms. The new script and traceability audit extension are installed automatically when the `.pdeq` submodule is bumped.

## Semantic

### Files

- `product/**/*.md`
- `design/**/*.md`

### Prompt

You are migrating a pdeq consumer project to version 0.10.0, which enforces living-spec discipline via a temporal language audit.

**Your task:**

1. **Scan for temporal language** by running `./scripts/audit-temporal.sh`. This will report findings like:
   - "MVP will include X"
   - "phase 1 has Y"
   - "V2 will add Z"
   - "iteration 2 adds..."
   - "will be implemented"
   - "planned for"
   - "will support", "will include", "will enable" (future-tense constructions)
   - "not yet" (implies future existence — use "does not" instead)
   - "establishing a pattern" (setup framing — describe what IS, not what is being set up)
   - "laying the groundwork" (planning language — describe present state)
   - "under development" (WIP marker — describe shipped state or omit)

2. **For each finding**, you must do ONE of:
   - **Rewrite in present tense** if the work has shipped: "MVP will include X" → "X is supported"
   - **Move to roadmap** if it describes future work: create or update `roadmap/<feature>.md` with the forward-looking content, using roadmap slug prefixes (`FRR-`, `NFRR-`, `ACR-`) if structured detail is needed
   - **Delete** if the language is stale and no longer relevant

3. **Preserve all authoritative content.** Do not remove requirements, acceptance criteria, or test cases just because they're phrased with temporal language — rewrite them in present tense.

4. **Opt-out / customization**: If patterns in the default list collide with domain terms (e.g., the product is literally called "MVP", or the team uses "iteration" as a standard development term):
   - **Granular**: Set `temporalAudit.exclude` in `pdeq.json` to list exact pattern strings to remove. E.g., `{"temporalAudit": {"exclude": ["\\bMVP\\b"]}}` removes only the MVP pattern while keeping all others.
   - **Add project terms**: Set `temporalAudit.include` to add patterns specific to your domain.
   - **Full replacement**: Set `temporalAudit.patterns` to replace all defaults entirely (ignores exclude/include).
   - **Blocking opt-out**: If the project has many findings and the user wants to defer cleanup, set `temporalAudit.blockCommit: false`.

5. **Re-run the audit** after changes: `./scripts/audit-temporal.sh`. If it still reports findings and the user did not opt out, keep cleaning until the audit is clean.

6. **Idempotency**: If `./scripts/audit-temporal.sh` reports no findings (or `temporalAudit.blockCommit: false` is already set), make NO changes. Output: `updated 0 of N files`.

7. **Final output**: Print exactly one summary line in this format:
   ```
   updated X of Y files (Z findings cleaned, or opted out via pdeq.json)
   ```

**What NOT to change:**
- Do NOT touch `roadmap/` files — temporal language is expected there
- Do NOT touch `decisions.md` or `decisions-pending.md` — historical context is legitimate
- Do NOT remove content, only reword or relocate it
- Do NOT create new features or requirements — only rewrite existing ones

**Example transformations:**

| Before (temporal) | After (present tense) |
|---|---|
| "The MVP will include email login." | "Email login is supported." |
| "Phase 1: basic auth" | "Basic auth is available." |
| "V2 will add OAuth support" | Move to `roadmap/<feature>.md` as `FRR-<feature>-oauth-support` |
| "This will be implemented later." | Delete (or move to roadmap if genuinely planned) |
| "Not yet implemented." | "Not implemented." (present tense — no future implication) |
| "Establishing a new pattern for future features." | "The pattern is: ..." (describe what IS) |
| "Laying the groundwork for X." | "X is available as ..." (describe present state) |
| "Under development." | "Shipped in v0.X." or delete |

Begin the migration. If the audit is already clean or the opt-out is set, output `updated 0 of N files` immediately.

## Notes

- **Roadmap slug prefixes**: `FRR-` (functional), `NFRR-` (non-functional), `ACR-` (acceptance criterion). These are exempt from traceability and never appear in `index.md`.
- **Graduation flow**: When a roadmap section is ready for implementation, renumber its slugs (`FRR-` → `FR-`) and move content into the authoritative product spec.
- **PDEQ_ALLOW_DRIFT=1**: Emergency escape hatch still bypasses the commit-time check.
- **Pristine specs philosophy**: Warnings create technical debt. Temporal language is blocked by default to enforce living-document discipline.
