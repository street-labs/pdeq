# QA Coverage Audit — CLI Test Plan

> Based on requirements in `../../product/coverage-audit.md`
> Based on engineering spec in `../../engineering/cli/coverage-audit.md`
> (No design spec — feature has no UI surface.)

## What We're Testing

This plan verifies the standalone `scripts/audit-coverage.sh` end-to-end: the index.md parsing, feature grouping, QA Coverage Matrix reading and parsing, the join logic that detects code-without-coverage, the prose-row skip, the NFR/AC warn-only behavior, the escape hatch, and the performance/determinism NFRs. Everything is shell-testable — no live agent required. Fixtures are temporary directories seeded with a minimal spec tree + index + QA matrices, exercised through the audit script with env overrides.

## Test Strategy

### Tooling

- **Primary harness**: plain POSIX shell test scripts using the same conventions as the code-mapping tests (`tests/lib/assert.sh`).
- **New assertion helpers**: `assert_audit_exits <code>`, `assert_stderr_contains <substr>`, `assert_stderr_not_contains <substr>`.
- **Fixture builder**: `make_fixture <template>` creates a temp directory with the fixture's contents.
- **Perf harness**: `bench.sh` wraps the audit with `/usr/bin/time -f '%e'`, runs three times, reports median.

### Env overrides used

- `PDEQ_ALLOW_DRIFT=1` — enables escape-hatch tests.
- `PDEQ_CONFIG_PATH` — overrides pdeq.json path for fixtures.
- `NO_COLOR=1` — disables ANSI escapes for clean stderr comparison.

### Automation split

All test cases in this plan are `[auto]` — the feature has no judgment-based branches.

## Edge Cases & Error Scenarios

### Missing index.md
- **Trigger**: `index.md` does not exist in the repo root.
- **Expected behavior**: Exit 1 with descriptive error. The audit cannot determine which features have code without the traceability index.
- **Test case**: Covered by `TC-coverage-audit-malformed-index` (missing index is a stronger form of malformation).

### Empty QA matrix (header only, no data rows)
- **Trigger**: QA Coverage Matrix has the header row but no data rows.
- **Expected behavior**: No rows to check. If the feature has code, this means there are no coverage obligations → pass.
- **Test case**: `TC-coverage-audit-code-exists-pass` variant with empty matrix.

### Coverage Matrix with unexpected status value (e.g., "Skipped", "N/A")
- **Trigger**: A row has status "Skipped" or some other unrecognized value.
- **Expected behavior**: Treated as non-terminal (since only Pass/Fail are terminal). Blocks if code exists.
- **Test case**: `TC-coverage-audit-mixed-status` with a row having an unrecognized status.

### Feature has code on one platform, QA file exists on another platform only
- **Trigger**: Code exists for a web feature but the QA file exists under `qa/mobile/` only.
- **Expected behavior**: The audit probes all platforms from `pdeq.json`. If no QA file exists for the platform where code exists, a warning is printed for the missing file, but no block (the feature has no coverage obligations recorded).
- **Test case**: `TC-coverage-audit-missing-qa-file`.

### Case sensitivity of status values
- **Trigger**: Coverage matrix row has status "pass" (lowercase) instead of "Pass".
- **Expected behavior**: "pass" is not in the terminal set {"Pass", "Fail"}, so it is treated as non-terminal. Blocks.
- **Test case**: Add a variant test that exercises case sensitivity.

## Regression Considerations

- **Existing audit-traceability.sh** must keep working after the QA parser is extracted to `scripts/lib/qa-matrix.sh`. The regression test runs the full traceability audit on the current pdeq repo before and after the extraction; output must be identical (modulo any source-line changes in the script itself).
- **CI pipeline** — adding `audit-coverage.sh` should not affect the other audits' CI jobs. The new script is wired as a separate step.
- **Pre-commit hook** — if `audit-coverage.sh` is added to the hook chain, it must not interfere with the other hooks' exit codes or stderr output. Run all hooks together on a fixture to confirm.
